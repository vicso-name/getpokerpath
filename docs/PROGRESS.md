## Decisions recorded

**Evaluator:** written in-house with no dependency. It classifies five cards and tries every five-card subset, C(7,5)=21 for seven cards. This is simple and fast enough for a UI. A future equity engine (P02) needs something faster and can sit behind the same contract.

**Royal flush:** its own category for display, as the brief asks for 10. It compares above every straight flush. The usual 7,462 figure counts it as the top straight flush.

**5-card vs 7-card flows:** both ship, as a mode switch. Hold'em is the default and reads a hand from the flop onward. A winner appears only once all nine cards are set. Each mode keeps its own cards.

**"No duplicate suits/ranks"** in `docs/MVP_WAVE_1.md` is read as no repeated physical card.

**Ties:** suits never break a tie. "Plays the board" is reported only when the board alone equals both players' hands.

**Accessibility:**

- Card controls are named like `King of hearts, K`, so the printed rank is in the name (WCAG 2.5.3). axe flags the same text in parentheses, which is why it uses a comma.
- Suit glyphs render through CSS as icons, since the name already states the suit.
- Used cards use `aria-disabled`, not `disabled`, so keyboard focus survives a pick.

**Position names:** 6-max uses UTG, HJ, CO, BTN, SB, BB. 9-max uses UTG, UTG+1, MP, LJ, HJ, CO, BTN, SB, BB. Names for the seats between UTG and the Cutoff vary: the 9-max MP is also called UTG+2, and the 6-max HJ is often called MP. The page says so.

**Heads-up:** in the model and explained on the page, but not a table option, because the brief lists 6-max and 9-max for the tool.

**Practice:** every position can be a target, including the Button. The dealer button moves clockwise after each question, so memorizing a seat number doesn't work.

**Not built:** a draggable dealer button, suggested by the research spreadsheet. Move dealer button does the same job and works by keyboard.

**Calls that differ from the bet (P09):** the three amounts alone can't always give a correct number, so the calculator doesn't guess.

- Call equals bet: the formula applies directly.
- Call larger than bet: refused. With P defined as the pot before the bet, a call can't exceed the bet.
- Call smaller than bet: no number until the user says why, because the same amounts can mean different things. P=100, B=100, C=40 needs 16.67% if every chip can be won, but 22.22% if the player is all-in for 40, since the other 60 goes back to the opponent.
  - Chips already in, or several opponents: the amounts stand as entered.
  - All-in for less against one opponent, with no chips in this round yet: the unmatched part is removed before the formula runs.
  - Any other all-in, including side pots: no number. The tool explains which amounts to enter instead.

**Zero amounts (P09):** all zeros has no valid percentage. A call of 0 reports that nothing is owed rather than showing 0%. P=0 with a real bet is allowed, because the math is valid.

**Decimal handling (P09):** amounts accept 2 decimal places, enough for dollars and for big blinds. The limits are shown next to the fields.

**Not built (P09):** the optional "your estimated equity" field in `docs/MVP_WAVE_1.md`, which the Stage 3 brief does not list. There is no link to P02, which isn't published.
