# SEO and information architecture

## Fixed assumptions

- Brand: **GetPokerPath**; intended canonical origin: **https://getpokerpath.com**. Treat deployment and DNS as pending; use centralized Astro site config for absolute URLs.
- US/EN initial market; all public copy in natural, helpful English.
- 15 pages approved as **planned canonical URL map**, not as 15 routes to publish immediately.
- Source: YepAPI estimates and 15 supplied SERP snapshots (2026-10-30). Volume/KD are directional, some KD=0 values may be missing/unreliable; ranking positions change.
- A user query = intent, not an instruction to create a separate page for every keyword variation.

## Indexable Wave 1 routes

- `/` — distinct brand/home narrative; entry points to three real tools.
- `/tools/` — usable directory of the three released tools, not a list of empty cards.
- `/poker-hand-rankings/` — P01; hand strength reference and actual comparison.
- `/poker-positions/` — P05; educational table and trainer.
- `/poker-pot-odds-calculator/` — P09; mathematical calling calculator.

## Critical page boundaries

- P02 `/poker-odds-calculator/` = showdown **equity / win probability from cards or ranges**. P09 `/poker-pot-odds-calculator/` = **price of a call from chip amounts**. They are different tools.
- P03 `/how-to-play-poker/` = guided beginner journey; P04 `/texas-holdem-rules/` = detailed Hold'em-specific mechanic simulator.
- P06 `/preflop-charts/` = curated vetted fixed presets; P07 `/poker-ranges/` = editable range builder. Their visible purpose must be distinct.
- P01 contains general ranking and cheat-sheet material; do not create several duplicate ranking pages without new validated user intent.

## Publishing and SEO guardrails

- Only publish routes after the tool is functional. Do not put indexable 'Coming Soon' pages into sitemap.
- Each route gets one real H1, distinct title/meta, visible explanatory HTML, relevant FAQ if useful, meaningful internal links and a stable canonical when `SITE_URL` is real.
- Have a crawlable Home→Tools→Tool architecture and cross-link tools when both exist. Do not link to unbuilt 404s.
- Use semantic HTML and descriptive buttons/labels; React islands should not hide the only useful content behind JS.
- Title/description examples in the Excel are **drafts**, not immutable text. Validate SERP snippets before finalizing.
- Avoid keyword stuffing, autogenerated thin content and manufactured review schema.
